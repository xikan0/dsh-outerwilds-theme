# 0.1.6 首次启用修复测试记录

## 0.1.6-beta.1 · 2026-10-20

### 实际失败证据

用户反馈正式下载 0.1.5 后，Desktop 原本为深色时点击“启用深色主题”仍失败，提示“保存失败，已恢复已保存的设置。”本轮用户提供的真实 settings/mutate 响应为：

```json
{
  "ok": false,
  "error": {
    "code": "settings/rejected",
    "message": "No configurable plugin entry \"ui-outerwilds-theme\"",
    "details": { "ns": "ui-outerwilds-theme" }
  }
}
```

这不是 0.1.5 处理的 settings/conflict。此前测试与用户验收记录保留为当时观察，不能据此推断此次入口缺失已修复。Desktop 磁盘安装的 0.1.5 客户端与已发布客户端一致；仅检查磁盘版本不能证明运行中的宿主入口已同步。

### 复现与定位

先重放用户响应，确认控制器会显示完全相同的红字。随后按热安装未同步、入口 ID 重复、配置模块未就绪的顺序核对；本机 profile 中主题 bundle 只有一项，主题配置为单独的覆盖项。

冷启动时已加载主题的两个隔离场景均能保存，不能作为此次问题已修复的依据。新的最小复现使用独立 DSH_HOME 和本机 DSH 0.2.1-rc.2：

1. 以原生深色启动宿主，起初不加载主题 bundle。
2. 模拟安装后将主题加入 profile；在宿主入口尚未同步时调用插件启用。
3. 原路径只调用 theme.setTheme('dark')。DSH 对相同偏好直接返回，不发生原生设置写入。
4. 主题设置请求得到与用户完全相同的 settings/rejected 和入口缺失信息。
5. 保持深色，先完成原生 ui-theme.preference=dark 的表单写入，再提交主题 enabled=true，两次写入都成功。

原生设置写入会通过宿主的正常配置编辑流程协调 profile 入口。这里修复的是已经实际复现的入口同步路径，不将所有设置拒绝都视为同一原因，也不依赖切换到浅色或无限重试。

### 实现与保护

- 生产客户端向控制器提供原生 ui-theme 表单；独立预览保留内存主题服务的原有行为。
- 启用操作在同一保存生命周期内等待原生深色偏好保存成功，然后再保存主题启用。其他主题偏好仍由原有表单管理。
- 原生表单只读、未就绪、拒绝或抛出异常时，不继续提交主题写入。
- 等待期间阻止重复启用与恢复默认；卸载、更新的关闭操作及失去写权限会阻止后续启用。过期操作不覆盖较新的保存结果。
- 保留现有版本冲突恢复、字号兼容、外观和音频设置，不扩展本轮功能。

### 自动检查

4 项新增回归在修复前均失败，在修复后均通过；覆盖原生写入顺序、失败保护、生命周期及实际设置按钮。全部 58 项测试和类型检查通过。

使用提取的真实 ConfigForm、设置镜像、ThemeRuntime 及真实宿主 RPC，修复后的热安装场景连续三次从 namespace unavailable 转为 enabled=true，均显示“已保存”，偏好始终为 dark，没有任何 light 写入。这是设置链路验证，不替代 Electron 真实界面验收。

本地诊断及原始响应保存在 `.sandbox/diagnostics/activation-0.1.6/`；安装包、配置备份和安装核对保存到 `.sandbox/iterations/0.1.6-beta.1/`。本轮不提交、不推送、不发布正式版本。Web 按约定安装启动后由用户自行打开审查，Desktop 在用户确认完全退出后同步；实际安装和运行结果完成后另行记录。

### 首次安装验收状态重建

用户进一步明确：问题主要出现在刚安装、DSH 已为深色、插件主题从未启用时。此前隔离探针验证的是入口未同步时的设置链路，不能替代用户在干净配置上的首次点击；现有普通 Web profile 也包含历史主题配置，不作为本轮首次安装的人工验收页。

用户明确授权“已退出，可以重置”后，仅对 Desktop 中这款主题执行可恢复的首次安装状态准备：

1. 确认 Desktop 主程序及宿主已退出，备份当前 profile 的配置、清单、锁文件和已安装主题，核对备份校验值。
2. 使用官方 CLI 卸载主题，清除 profile 中仅属于 ui-outerwilds-theme 的旧配置；其余配置按 YAML 语义逐项比对不变。
3. 重新安装同一份 0.1.6-beta.1 测试包。确认主题没有任何已保存配置，安装包的 enabled 与 audioAuto 默认均为 false，原生偏好仍为 dark。
4. 核对其他 11 个插件的声明、实际版本、相对 bundle 顺序及原生主题配置保持；未读取或改动聊天数据。
5. 不启动 Desktop、不代替用户点击启用，保留第一次点击给用户。

此次清除了该主题自身的旧选择，包括它原先的音频响应选择；这些内容均在新备份中，不误记为“主题设置也全部保留”。其他插件与 DSH 原生深色设置保持。

- 清理前的完整备份：`.sandbox/iterations/0.1.6-beta.1/desktop-first-install-reset/`。
- 已清理且尚未重装时的 profile 备份：同目录下的 `desktop-profile-before-first-install/`。
- 清理、重装与首次点击前状态：`desktop-first-install-clean-check.json`、`desktop-first-install-check.json`、`desktop-first-install-ready.json`。
- 安装包和客户端校验值与前述 0.1.6-beta.1 一致，本次未改变修复代码或重建安装包。

验收步骤：用户重新打开 Desktop 后，应仍显示 DSH 原生深色背景；进入“星际拓荒”，按钮应为“启用深色主题”。不要先切浅色，也不要先开关主题，直接第一次点击该按钮，检查是否应用主题且没有红字。若打开时主题已被自动启用，先停止操作并反馈，这不能算作首次启用通过。
